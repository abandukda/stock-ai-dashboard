# Source receipts and private customer composition release

Base: `8d42d762e78dba4441f7645eaeb3b4ce331d37ee`.
This is a review candidate, not authorization to deploy or operate providers.

## Resulting behavior

This release connects two independently testable boundaries: executor-recorded
source capture times and explicit private customer routing. It does not enable
either acquisition or production beta configuration.

- Gateway receipts bind each response and final run completion to versioned UTC
  windows. History review rejects substituted/legacy/unattested capture times
  and candles whose own response preceded the finalized session. Existing raw
  evidence remains unchanged. See `ATLAS_GATEWAY_CAPTURE_TIME_REVIEW.md`.
- An explicit server-owned binding supplies the existing individual account
  controller, admitted retained rows and optional read-only Earnings cache to
  actual app dispatch. Default startup remains on its existing password path.
  Native accounts cannot inherit administrator aliases or shared watchlists.
  Every route checks current membership/capabilities; account changes discard
  private presentation/handoff state. Source availability and account access
  remain separate. See `ATLAS_CUSTOMER_RUNTIME_COMPOSITION.md`.
- Actual mobile visual review caught a truncated unavailable Earnings decision.
  Textual states use escaped wrapping cards; numeric calculations and missing
  evidence semantics are unchanged.

Generated identities, candle fixtures and transcript summaries are not financial
evidence or production account acceptance. All exact-head governed checks must
pass before review approval; merge/deployment needs owner approval. Public
Report Card remains OFF. No source/ledger mutation, licensed/paid call, protected
routing or infrastructure change is part of this release.

## Existing production recovery is separate

Current production QA directly observed held projection/reader body mismatch.
This candidate does not hot-reload financial modules or silently repair that
process. `ATLAS_PRODUCTION_RUNTIME_RECOVERY.md` records exact evidence and the
separate owner-approved clean app reboot/read-only QA package. Passing this
candidate's tests cannot certify the already-running process.
